# V1.5 Bulk Pricing — per-order quantity tier system

> **STATUS: SPEC ONLY — NOTHING SHIPPED.** V1.5 Track C extension (Bulk). Locked 2026-06-04 alongside the V1.5 velocity tier model. This doc covers the BULK pricing track. On-demand pricing lives in `_V1.5_VELOCITY_PRICING.md`.

> Bulk and on-demand are economically different and now have separate tier systems. Bulk = per-order quantity tier (single-order discount); on-demand = per-SKU 30-day rolling velocity tier. Cross-pollination preserved: bulk units still count toward the on-demand velocity tier.

## The two-layer pricing model

A bulk order at quantity Q computes as:

```
unit_price(Q)       = manufacturer_wholesale_tier_price(Q)        // partner-set ladder, MOQ-anchored
+ platform_fee(Q)   = platform_fee_pct(subscription_tier) × unit_price(Q)
+ setup_fee         = partner_set per-tier flat (nullable)
+ shipping          = computed from carrier + weight + destination
× quantity          = Q

Quote = (unit_price + platform_fee) × Q + setup_fee + shipping
```

**Layer 1 — Manufacturer wholesale tier ladder.** Partner-set, MOQ-anchored. Per category we seed 11 standardized brackets (table below) that the partner can adopt or customize per product.

**Layer 2 — Platform fee.** iLaunchify-set, applies as a % of the wholesale unit price. Base rate comes from creator's subscription tier (Maker 15%, Builder 10%, Agency 7%). For bulk, the platform fee is FLAT % (not velocity-discounted) — bulk's pricing leverage is in the wholesale tier ladder, not the platform fee.

Transparency contract: every checkout shows `wholesale × Q + platform fee × Q + setup fee + shipping = total`. Creator always sees the breakdown.

## Category bracket ladders (V1.5 platform-suggested defaults)

These auto-populate when a partner adds a product in the matching category. Partner can customize any threshold or price. Outliers render a "Custom pricing" badge in creator marketplace.

| Tier | Supplements | Beverages | Snack food | Pet products | Cosmetics | OTC pharma |
|---|---|---|---|---|---|---|
| T1 | 100–249 | 500–999 | 500–999 | 100–499 | 250–499 | 1,000–4,999 |
| T2 | 250–999 | 1,000–4,999 | 1,000–4,999 | 500–1,999 | 500–1,999 | 5,000–19,999 |
| T3 | 1,000–4,999 | 5,000–19,999 | 5,000–19,999 | 2,000–9,999 | 2,000–9,999 | 20,000–49,999 |
| T4 | 5,000–14,999 | 20,000–49,999 | 20,000–49,999 | 10,000–29,999 | 10,000–29,999 | 50,000–99,999 |
| T5 | 15,000–49,999 | 50,000–99,999 | 50,000–99,999 | 30,000–99,999 | 30,000–99,999 | 100,000–249,999 |
| T6 | 50,000+ | 100,000+ | 100,000+ | 100,000+ | 100,000+ | 250,000+ |

Six visible tiers per category (vs Supliful's eleven) — fewer brackets reduces partner-editor friction and creator decision paralysis. Partner can subdivide further if they want.

Reasoning for the spread:

- **Beverages + snack food** start at 500 because production-line setup (depalletizing, labeling, sealing) makes <500-unit runs uneconomical
- **Supplements** start at 100 because encapsulation lines run efficiently at modest scale
- **Pet products** mirror supplements/food hybrid behavior
- **Cosmetics** start at 250 — industry-standard MOQ floor for indie beauty
- **OTC pharma** starts at 1,000 due to clean-room + regulatory setup overhead

These thresholds also drive marketplace UX: if a Maker requests 50 cosmetic units, the system surfaces "below MOQ — use on-demand instead" with a live cost comparison.

## MOQ-anchored activation

```
Product.moq = 100             // partner-set per product
Product.moqRoundingPolicy = SUGGEST_ON_DEMAND  // default
Product.quantityStep = 1       // for non-case-packed products

ProductBulkTier rendering:
  T1 (100–249) → ACTIVE, $7.84/unit
  T2 (250–499) → ACTIVE, $7.11/unit
  T3 (500–999) → ACTIVE, $6.74/unit
  ... etc.

If Product.moq = 500:
  T1 (100–249) → N/A (greyed)
  T2 (250–499) → N/A (greyed)
  T3 (500–999) → ACTIVE — first available tier
```

Standardized brackets remain visible across all products (creator UX consistency), but tiers below MOQ render greyed/disabled and reject quote requests. Matches Supliful's display pattern.

## Schema additions

```prisma
model Product {
  // existing fields …
  moq                  Int                       // partner-set, default from category
  maxOqPerBatch        Int?                      // null = no upper cap
  moqRoundingPolicy    MoqRoundingPolicy         @default(SUGGEST_ON_DEMAND)
  quantityStep         Int                       @default(1)  // 1, 6, 12, 24, etc.
  bulkTiers            ProductBulkTier[]
}

enum MoqRoundingPolicy {
  REJECT_BELOW          // refuses quote requests below MOQ
  ROUND_UP_TO_MOQ       // produces MOQ, charges for MOQ, ships MOQ
  SUGGEST_ON_DEMAND     // default — surfaces on-demand cost comparison
}

model ProductBulkTier {
  id                   String                    @id @default(uuid())
  productId            String
  product              Product                   @relation(fields: [productId], references: [id])
  tierIndex            Int                       // 1..6 within category bracket structure
  qtyMin               Int
  qtyMax               Int?                      // null = open-ended (top tier)
  unitPriceUsd         Decimal?                  @db.Decimal(12, 4)  // null = N/A (below MOQ)
  setupFeeUsd          Decimal?                  @db.Decimal(12, 2)  // null = no setup fee
  leadTimeDays         Int                       // partner-set per tier
  createdAt            DateTime                  @default(now())
  updatedAt            DateTime                  @updatedAt
  decorations          ProductBulkTierDecoration[]

  @@unique([productId, tierIndex])
  @@index([productId])
}

model ProductBulkTierDecoration {
  // Which decoration methods unlock at which tier
  bulkTierId           String
  bulkTier             ProductBulkTier           @relation(fields: [bulkTierId], references: [id], onDelete: Cascade)
  decorationMethodId   String
  decorationMethod     DecorationMethod          @relation(fields: [decorationMethodId], references: [id])

  @@id([bulkTierId, decorationMethodId])
}

model CategoryBulkTierTemplate {
  // Platform-seeded category default brackets — admin-tuneable
  id                   String                    @id @default(uuid())
  categoryId           String
  category             ProductCategory           @relation(fields: [categoryId], references: [id])
  tierIndex            Int
  qtyMin               Int
  qtyMax               Int?
  suggestedUnitPriceUsd Decimal?                 @db.Decimal(12, 4)  // optional hint
  notes                String?

  @@unique([categoryId, tierIndex])
}

model BulkQuoteSnapshot {
  // Frozen pricing for a creator's pending bulk order
  id                   String                    @id @default(uuid())
  creatorUserId        String
  productId            String
  quantity             Int
  unitPriceUsd         Decimal                   @db.Decimal(12, 4)
  setupFeeUsd          Decimal                   @db.Decimal(12, 2)
  platformFeePct       Decimal                   @db.Decimal(5, 2)
  shippingUsd          Decimal                   @db.Decimal(12, 2)
  totalUsd             Decimal                   @db.Decimal(12, 2)
  appliedTierIndex     Int
  quotedAt             DateTime                  @default(now())
  expiresAt            DateTime                  // quotedAt + 7 days
  consumedByOrderId    String?                   @unique

  @@index([creatorUserId])
  @@index([expiresAt])
}

model BulkTierAudit {
  // Every change to ProductBulkTier or CategoryBulkTierTemplate
  id                   String                    @id @default(uuid())
  changedAt            DateTime                  @default(now())
  changedByUserId      String
  entityType           String                    // 'ProductBulkTier' | 'CategoryBulkTierTemplate'
  entityId             String
  fieldName            String
  oldValue             String?
  newValue             String?

  @@index([entityType, entityId])
}
```

CockroachDB compliance: bare `String` (no `@db.Text`), `@id @default(uuid())` not `cuid()`, all migrations additive. Decimal precision tuned to avoid currency rounding errors.

## Mixed-flavor multipack rule (locked)

When a creator orders multiple flavors of the same `ProductTemplate` in a single bulk run:

```
Creator orders: Honey-Vanilla 100u + Honey-Maple 100u + Honey-Original 100u = 300 total

Per-SKU (LOCKED):
  Each flavor priced at Tier 1 (100–249)
  3 × (100 × Tier 1 price) + 3 setup fees
  Three separate production runs

NOT Aggregate:
  Would price all 300 at Tier 2 (250–499)
  Single combined run
```

**Why per-SKU:** the manufacturer's production runs ARE per-flavor (different fillers, different label print plates, different changeover cleaning). Pricing must match production economics. A creator who wants the aggregate discount needs to commit to a single-flavor bulk run.

This must be surfaced clearly in the creator checkout: a 3-flavor 300-unit cart shows "3 × Tier 1" not "1 × Tier 2", with an explainer tooltip linking to documentation.

## Sub-MOQ request flow

Creator requests 150 units of a product with MOQ 250:

```
Default (SUGGEST_ON_DEMAND):
  ┌─────────────────────────────────────────────────────────────┐
  │ Below MOQ for bulk. Here's what 150 units costs:            │
  │                                                              │
  │ Via on-demand:   150 × $11.50 = $1,725  (ships in 3 days)   │
  │ Via bulk @ MOQ:  250 × $7.84  = $1,960  (ships in 21 days,  │
  │                                          you receive 250)    │
  │                                                              │
  │ [ Place on-demand order ]  [ Bump to MOQ ]  [ Cancel ]      │
  └─────────────────────────────────────────────────────────────┘

REJECT_BELOW (partner override):
  "Bulk MOQ is 250 units for this product. Try on-demand instead."

ROUND_UP_TO_MOQ (partner override):
  "You'll receive 250 units. Pay for 250. Excess is yours to keep."
```

`SUGGEST_ON_DEMAND` is the default because it converts a hard reject into a sale.

## Quote snapshot governance (locked)

Every bulk quote captures `BulkQuoteSnapshot` row at the moment the creator clicks "Get quote". Snapshot frozen for 7 days. During those 7 days:

- Partner can change underlying `ProductBulkTier` prices, but the creator's quote remains at snapshot prices
- If the creator converts the snapshot to an order within 7 days, the order ships at snapshot prices
- If 7 days expire without conversion, snapshot voids; creator must re-quote
- Every tier price change writes `BulkTierAudit` row with old/new value, timestamp, actor

This is non-negotiable for legal — a creator who commits to a bulk run cannot be price-bumped after the fact.

## Lower-of pricing (carry over from velocity model)

If at quote time the creator's bulk-quantity-tier price comes out HIGHER than what their current on-demand velocity tier would charge for the same SKU + quantity, the system applies the lower price. Logic from `_V1.5_VELOCITY_PRICING.md` §"Lower-of pricing" extends to bulk: take min of (bulk_tier_price, velocity_tier_price) at quote time.

## Maker tier — full bulk access, base-fee differentiation

**Locked rule:** Maker creators have FULL access to manufacturer wholesale tier ladders AND all decoration methods AND all MOQ levels. The differentiation between Maker / Builder / Agency for bulk orders is the BASE FEE RATE, not access lockout.

| Tier | Bulk access | Wholesale tier ladder | Platform fee % |
|---|---|---|---|
| Maker | Full | Same prices as Builder/Agency | 15% |
| Builder | Full | Same prices | 10% |
| Agency | Full | Same prices | 7% |

**Why:** Pavel's bulk-first thesis. Bulk is the primary revenue stream. Locking Makers out of volume discounts contradicts that. The fee-rate differential is honest pricing for different service tiers; the access gate is artificial. Trust > extraction.

The break-even math is transparent to creators:

```
Maker doing 5,000-unit bulk: 5,000 × $6.74 × 15% = $5,055 platform fee
Builder doing same:           5,000 × $6.74 × 10% = $3,370 platform fee
  Saving: $1,685
  Builder subscription: $79/mo
  Builder is mathematically obvious for a creator running this volume monthly
```

## Partner tier model — Verified → Trusted → Anchor (LOCKED 2026-06-04)

Bulk pricing applies the same per-order partner fees as on-demand, using the locked partner tier ladder. **All three tiers are FREE in V1.5** — no partner subscription anywhere. Tier progression is admin-promoted at every step.

| Tier | Per-order fee | Subscription | How to reach it |
|---|---|---|---|
| **Verified** | 5% | $0 | Application approved + KYB |
| **Trusted** | 3.5% | $0 | Admin-promoted on performance (volume + reliability + on-time rate) |
| **Anchor** | 2% | $0 | Admin-promoted / invite-only — top-tier scale + strategic value |

The per-order fee differentiation is the only monetary reward for tier promotion in V1.5. Lower fee at higher tier rewards proven performance.

**Why no subscription anywhere in V1.5** (Pavel push-back 2026-06-04): the original spec staged Trusted as a paid subscription unlocking V2 advanced tools (3D Product Builder, AI image generation, etc.). Those tools don't exist yet. Charging for them in V1.5 would be unjustifiable. Subscription overlay is deferred to V2 conditional on shipping the advanced tools — at which point we revisit whether to gate-by-tier OR add a separate "Pro tools" overlay decoupled from trust signal.

The "Premier" name was renamed to "Anchor" 2026-06-04 to capture the load-bearing-pillar meaning more accurately and avoid pay-to-play connotations. See [[ilaunchify-partner-tier-progression]].
